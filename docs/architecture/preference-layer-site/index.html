기능 한눈에 — 무엇을 해주고 왜 있는가

상세 페이지의 각 함수 제목 아래에 "한다 · 왜 · 없으면 · 입출력" 카드가 있다. 여기는 그 요약이다.

2 · model.PreferenceModel
가중치 벡터 한 행
모델 파일이 아니라 숫자 1,548개(스칼라 11 · 임베딩 1,536 · bias · λ). 은닉층이 없어 추론에 런타임이 필요 없고, 행 하나로 "무엇으로 배웠고 얼마나 나아졌나"까지 남긴다.
2 · features.build
특징 x — pref-v1 계약
DB 에 이미 있는 값만으로 1,547 자리를 만든다. 순서가 계약이라 학습기와 wes 가 똑같이 조립해야 한다. 임베딩은 갤러리 평균을 뺀다.
3 · job.run_train
시험 → 학습 → 판정 → 저장
마감 갤러리 전부를 모아 홀드아웃을 먼저 재고 그 다음 전체로 학습한다. 학습에 넣기 전에 새 갤러리로 시험해야 점수가 부풀지 않기 때문에 순서가 이렇다.
3 · train.make_sample
라벨 규칙
양성 = 최종 선택(클러스터당 1), 음성 = 선택 없는 연사 클러스터의 대표, 양성의 연사 형제는 라벨 없음. 거의 같은 벡터에 반대 라벨을 주면 없는 경계를 그리게 된다.
3 · train.fit · train
로지스틱 회귀 한 번
갤러리별 벡터를 만들어 합치는 게 아니라 데이터를 합쳐 한 번 푼다. 부부마다 다른 취향은 상쇄되고 공통 방향만 남아 "부부 평균 취향"이 된다.
4 · evaluate.recalls · auc
recall@K (strict · cluster) · AUC
순위를 연사 클러스터당 1장으로 dedup 한 뒤 잰다. wes MmrSelector 가 그렇게 보여주므로 실제 노출과 맞는 쪽이 cluster 다.
4 · evaluate.gate
active 조건 셋
부호 검정 p<0.05 · 악화 갤러리 ≤30% · 최근 3회 추가에서 안정. 절대값이 아니라 쌍 차이의 부호로 본다 — 개선 폭이 완만할 것이기 때문.
5 · model.fuse (목표: wes)
z(prior) + λ·z(pref)
문턱값 없이 순위만 바꾼다. λ(n)=n/(n+5) 라 갤러리가 적으면 prior 에서 조금만 움직인다. active 행이 없으면 지금 점수와 비트 단위로 같다.
5 · wes (목표)
CLOSED 전이 → EVENT
갤러리가 마감될 때 Lambda 를 EVENT 로 부른다. galleryId 는 로그용이고 학습은 언제나 전부다. 하루 1회 EventBridge 로 대신해도 결과가 같다.
6 · 단계
1 → 2 → 3
코드(있음) → 배포·연결(없음) → 데이터가 쌓여야 게이트가 열린다. 셋째는 코드로 당길 수 없다.

원칙 다섯

  • 산출물은 행 하나다. ML 모델 파일도, S3 도, torch 도 없다. 로지스틱 회귀의 가중치 1,548개가 preference_models 한 행이고, 추론은 wes 가 내적 한 번. 임베딩·score 모델 버전이 행에 박혀 있어 버전이 바뀌면 wes 가 안 읽는다.
  • 매번 전부 다시 푼다. 갤러리별 벡터를 만들어 합치지 않는다. 마감 갤러리 전부의 사진·선택을 한 표로 합쳐 새로 풀고 이전 벡터는 버린다. 결과는 "부부 평균 취향"이고 부부별 편차는 기존 in-session 항(deficit·lift)이 맡는다.
  • 학습에 넣기 전에 시험한다. 홀드아웃은 벡터가 아니라 점수 한 줄을 만든다. 학습에 들어간 갤러리에서 재면 자기가 배운 걸 다시 푸는 셈이라 부풀려진다(in-sample 0.86 vs 하나 빼고 0.55). 나아진 게 유의할 때만 active.
  • 순위만 바꾸고 자르지 않는다. pref 는 z 정규화해 λ 만큼 더할 뿐, 사진을 후보에서 빼는 문턱값이 아니다. 몇 장을 어디서 고르느냐는 지금의 폴더 쿼터와 MMR 그대로.
  • 안 붙어 있을 때는 아무 영향도 없다. active 행이 없으면 λ 항이 없어 지금 추천과 같다. 붙은 뒤에도 n 이 작으면 λ 가 작다(n=1 → 0.17, n=5 → 0.5). 소규모 데이터의 안전장치다.
