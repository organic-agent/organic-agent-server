언제 실행되나 — 세 진입점

한다잡이 CATEGORIZING 이고 배정 행과 백분위가 다 찼을 때 스윕이 자동으로, 또는 작가가 수동 API 로 materializeFromAnalysis 를 부른다. 갤러리 행 락 하나로 직렬화된다.왜자동 경로가 기본이라 사용자는 아무것도 누르지 않아도 폴더를 받는다. 수동 경로는 실패 뒤 재시도와 관리자 도구용이다. 락은 같은 갤러리의 물질화가 겹쳐 폴더 세트가 둘 생기는 것을 막는 가장 단순한 수단이다.없으면폴더가 버튼 한 번에만 생기거나, 스윕과 수동이 겹쳐 같은 잡의 폴더가 두 벌 생긴다.

실선은 호출·저장, 점선은 조회·상태 확인입니다. 박스를 누르면 해당 단계의 설명으로 이동합니다.

categorize 산출물이 폴더가 되기까지 — 값의 행선지

왼쪽은 categorize Lambda 가 DB 에 남기는 것, 가운데는 wes 가 그것을 관측·계산하는 코드, 오른쪽은 만들어지는 폴더 테이블입니다. 실선은 호출·저장, 점선은 조회·관측. Lambda 는 폴더를 만들지 않고 wes 스윕이 결과를 보고 만듭니다.

알고리즘 — createFromAnalysisLocked

한다최신 잡의 배정 행과 사진→그룹 매핑을 읽어 parent → ConceptFolder, concept → DetailFolder 로 폴더를 만들고, 아직 어느 폴더에도 없는 사진만 JDBC batch 로 배정한다. 같은 잡 세트가 있으면 그대로 반환(멱등).왜배정 행은 "그룹 → 이름"일 뿐 사진과 폴더의 관계가 아니다. 사진별로 그룹을 찾아 폴더에 넣고, 피사체 다수결로 칩을 달고, 리뷰 플래그를 폴더로 올려야 화면이 쓸 수 있다. "이미 배정된 사진 제외"가 사용자가 옮긴 사진을 보호하는 유일한 규칙이고, 멱등 단락은 재실행·중복 스윕을 무해하게 한다.없으면재분류 때 사용자가 손으로 옮긴 사진이 되돌아가거나, 재실행마다 폴더가 늘어난다.입출력galleryId → concept_folders · detail_folders · photo_category_assignments, 반환 List<ConceptFolderResponse>
  1. 갤러리 락. galleryRepository.requireWithLockById(PESSIMISTIC_WRITE). 폴더·배정 테이블에는 락을 걸지 않는다. 같은 갤러리의 물질화는 직렬화된다.
  2. 최신 잡의 배정 읽기. AiConceptAssignmentLoader.loadLatest — jobId가 가장 큰 배정 행들을 LatestAssignmentsDto(jobId, assignments)로 반환한다. 없으면 409 ANALYSIS_NOT_COMPLETE.
  3. 멱등 단락. (gallery_id, analysis_job_id = 최신 잡) 인 concept_folders 가 이미 있으면 새로 만들지 않고 DB 에서 읽어 그대로 반환한다.
  4. 사진 → 그룹 조인. photo_analysis JOIN photos(display_order, id 순)에서 photoId · embedGroupId · subjects · clusterId 네 컬럼만 읽는다(벡터 제외). 그룹이 null 인 미분석 사진도 포함해 "기타"로 보낸다.
  5. USER 배정 보호. photo_category_assignments 에 이미 있는 사진 전부(AI/USER 구분 없음)를 대상에서 뺀다. 이 한 줄이 재물질화가 사용자가 옮긴 사진을 건드리지 않는 근거다. 남은 사진이 0 이면 NO_PHOTOS_TO_ORGANIZE.
  6. 계획(planner). 사진을 (parent_name ?: "기타", concept_name ?: "기타") 로 묶는다. 용어가 뒤집혀 있다 — AI 테이블의 parent_name 이 wes 의 ConceptFolder(상위), concept_name 이 DetailFolder(하위) 이름이다.
  7. 세부폴더 칩 = 피사체 다수결. 폴더 안 사진들의 subjects(bride/groom/couple/group)를 세어 최빈값이 엄격 과반(count × 2 > size)일 때만 DetailFolderCategory(신부·신랑·두 분·단체) 채택. 동률이면 칩 없음.
  8. needs_review 전파. 폴더 안 사진의 그룹 배정 중 하나라도 needs_review 면 DetailFolder.needsReview = true(OR). confidence·assigned_by·proposed_parent·clip_parent 는 wes 가 읽지 않는다.
  9. 정렬. 세부폴더 안 사진은 embedGroupId, clusterId 순(null 은 뒤로). 세부폴더·컨셉폴더는 "기타"를 맨 뒤로 보내고 사진 수 내림차순. 컨셉 sortOrder 는 기존 컨셉 개수 뒤로 이어붙인다.
  10. 적재. ConceptFolder(createdSource=AI, analysisJobId) → DetailFolder(category, needsReview) → CategoryBulkWriter.insertAiAssignments 가 JDBC batch 로 photo_category_assignments(source=AI, confidence=NULL, assigned_by_user_id=NULL) INSERT. 반환은 DB 재조회 없이 메모리 조립.
createFromAnalysisLocked(galleryId):
  gallery  = SELECT … FROM galleries WHERE id=? FOR UPDATE
  latest   = ai_concept_assignments WHERE job_id = max(job_id of gallery)   // 없으면 409 ANALYSIS_NOT_COMPLETE
  if concept_folders(gallery_id, analysis_job_id=latest.jobId) 있음: return 그대로   // 멱등
  members  = photo_analysis ⋈ photos (galleryId) → {photoId, embedGroupId, subjects, clusterId}
  members -= photo_category_assignments.photo_id (gallery)                     // USER 배정 보호
  if members 비었음: throw 409 NO_PHOTOS_TO_ORGANIZE                           // 자동 경로에선 DONE
  plans = group members by (parent_name ?: "기타", concept_name ?: "기타")
          detail.category    = subjects 최빈값, count*2 > size 일 때만
          detail.needsReview = OR(그룹 배정.needs_review)
          정렬: "기타" 뒤로 → 사진 수 내림차순
  base = count(concept_folders of gallery)
  for (i, plan): INSERT concept_folders(sort_order=base+i, AI, latest.jobId)
      for (j, d): INSERT detail_folders(j, AI, d.category, d.needsReview)
                  batch INSERT photo_category_assignments(d.photoIds, source=AI)
  return 메모리 조립 응답

재물질화와 멱등성

  • 같은 잡 재실행 — 완전 멱등. 이미 있는 세트를 읽어 돌려준다(테스트 AiCategoryFolderServiceTest: created == reread == materialized).
  • 새 잡으로 재실행 — 기존 폴더를 재사용하지 않고 새 analysis_job_id 로 폴더 세트를 또 만든다. 이름 유니크 제약·병합 로직은 없다. 단, 사진은 "아직 어느 폴더에도 없는 것"만 담으므로 대부분 비고, 0장이면 아무것도 만들지 않는다.
  • 사용자 편집 보존 — USER 가 옮긴 사진·만든 폴더는 건드리지 않는다. 사용자가 사진을 미분류로 빼면(배정 행 삭제) 그 사진은 다음 물질화 대상이 된다.
  • 동시 실행 — 갤러리 락으로 직렬화, 두 번째는 이미 만들어진 세트를 보고 단락.

알림

AnalysisOrchestrator 가 잡을 DONE 으로 닫는 트랜잭션 안에서, 결과가 MaterializeOutcomeDto.Created일 때만 AnalysisCompletionNotifier.notifyFoldersCreated 를 부른다. 수신자는 워크스페이스 구성원 + gallery_members 전원(distinct), 유형 ANALYSIS_COMPLETED, 제목 "AI 분석이 완료되었습니다", 본문 "AI 폴더가 만들어졌습니다. 폴더를 확인해 주세요." 수동 API·관리자 경로는 알림을 보내지 않는다.

조회 API

GET /galleries/{g}/concept-folders → 갤러리의 모든 컨셉(AI 세트 + USER 폴더 섞어서) sortOrder, id 순. 응답은 ConceptFolderResponse{ id, name, sortOrder, createdSource, analysisJobId, details[{ id, name, category, needsReview, photoIds[] }] }. 사진 메타는 없고 id 배열만 내려간다.
