흐름 — job.run

실선은 호출·저장, 점선은 조회·상태 확인입니다. 박스를 누르면 해당 단계의 설명으로 이동합니다.

그룹 계산 — pipeline.group

한다DB 의 E(DINOv3)·C(CLIP)·원점수를 읽어 갤러리 전체를 매번 다시 계산한다: 백분위, 연사 클러스터, 임베딩 그룹, 연사 대표.왜백분위와 그룹은 "갤러리 안에서의 상대값"이라 사진이 늘면 전부 바뀐다. 갤러리 하나가 수 초면 끝나므로 증분보다 전체 재계산이 단순하고 정확하다. 원점수 대신 백분위를 쓰는 이유는 모델을 바꿔도 비교가 가능하고 추천 산식이 단위에 흔들리지 않기 위해서다.없으면새 사진이 오면 옛 백분위와 새 백분위가 섞여 순위가 거짓이 되고, 연사·그룹이 사진 추가 전 기준으로 굳는다.입출력photo_analysis(E, C, scores) → technical_pct · aesthetic_pct · cluster_id · cluster_rank · embed_group_id · sub_scores(+sharpness_pct, rank_reason)
  1. 결합. store.read_gallery 한 쿼리로 분석 행·E(DINOv3)·C(CLIP)를 받는다. 행은 model_version == "photoselect-v3-a-0.1" 인 것만 쓰고, 셋 중 하나라도 없는 사진은 경고 후 제외, 전부 없으면 RuntimeError. embedding_model 이 갤러리 안에 섞여 있으면 거부. 그룹화가 만든 행과 concat 공간은 Grouped 로 naming 에 넘어가 naming 은 DB 를 다시 읽지 않는다(예전엔 셋을 두 번 읽고 X 를 두 번 만들었다 — 7천 장이면 벡터 44MB 두 번).
  2. 백분위. technical_score → technical_pct, aesthetic_score → aesthetic_pct, sharpness → sub_scores.sharpness_pct. 갤러리 내 순위 100·rank/(n−1), NaN 은 50(없는 신호가 순위를 흔들면 안 된다).
  3. 연사(cluster.py). 카메라(make+model)별 파티션 → 파티션 안 모든 사진에 taken_at 이 있을 때만 시간순 정렬 → 창 8 안 이웃과 DINOv3 코사인 ≥ 0.96 이면 union-find 병합 → 등장 순 cluster_id. 파티션 경계는 넘지 않는다.
  4. concat 공간. normalize([normalize(E) ⊕ normalize(C)]) — 코사인 = 두 공간 코사인의 평균.
  5. 임베딩 그룹(concept.py). 평균연결 계층 클러스터(linkage(average, cosine))를 거리 0.2 에서 자른다. 적응 규칙: 과병합(그룹 < min(4, n) 또는 최대 그룹 > n×0.5)이면 0.05 씩 하강(하한 0.05); 하강이 불필요했고 과분할(그룹 > max(4, n×0.35))이면 0.05 씩 상승(상한 0.35), 상승이 과병합을 만들면 한 걸음 되돌림 → embed_group_id(등장 순).
  6. 연사 대표. 클러스터별 (−technical_pct, −sharpness, −aesthetic_pct, photo_id) 정렬 → cluster_rank 0,1,2… rank 0 에 rank_reason: single / technical(차 > 5) / sharpness(> 1.25×) / aesthetic(차 > 5) / tie.
근거 (config.py 주석)
"2026-08-29 갤러리 1 실측(DINOv2, 822장): 평균연결 거리 0.2 에서 70그룹 — 케이크 세트 50·해변 41·소파 39·정원 37·덩굴 아치 36장으로 촬영 세트와 일치. 0.3 부터 다른 세트가 섞인다." "concat 0.2 에서 58그룹, DINOv3 단독과 ARI 0.95." 연사 0.96·그룹 0.2 는 CLIP/DINOv2 시절 값이라 DINOv3 기준 재측정 대상.

이름 붙이기 — naming.run

한다그룹마다 대표 사진 1~2장을 골라 Sonnet 에 보내 {parent, concept, confidence} 를 받고, 표기를 통일하고, 못 보낸 소그룹은 최근접 그룹 이름을 물려받으며, 의심스러운 그룹에 needs_review 를 단다.왜폴더 이름은 사람이 읽을 것이라 모델의 열린 답이 필요하지만 사진 전부를 보내면 비용이 갤러리 크기에 비례한다. 그룹 대표만 보내고 커버리지 85%·상한 120 으로 자르면 호출이 ⌈이미지/15⌉+1 로 묶인다. 부모는 고정 목록(enum)으로 강제해 상위 폴더가 흔들리지 않게 하고, CLIP 부모 다수결과 대조해 사람이 볼 곳만 표시한다.없으면7천 장 갤러리가 수백 번의 VLM 호출이 되거나, 부모 이름이 갤러리마다 달라 상위 폴더가 난립하고, 오배정을 사람이 찾을 방법이 없다.입출력embed_group_id[] → ai_concept_assignments(job_id, embed_group_id, parent_name, concept_name, …)
  1. 그룹 선택. 크기 내림차순으로 사진 커버리지 85% 에 이를 때까지, 최대 120 그룹. 나머지는 ⑪ 로.
  2. 대표 사진. concat 공간 중심(평균 정규화)에 최근접 1장. spread = mean(1 − sim) > 0.12 면 최원점 1장을 더한다(대표 2장이 서로 다른 세트로 보이면 confidence 를 낮추라고 프롬프트에 적혀 있다). 미리보기는 store.preview_paths 가 대표 전부의 preview_key 를 SELECT 한 번(id = ANY)으로 받아 스레드 16개로 S3 에서 병렬 다운로드하고, 긴 변 768 JPEG q80 축소도 스레드 8개로 겹친다(예전엔 사진마다 SELECT + GET 직렬, 대표 240장에 10~25초). 이미지 블록으로 보낸다. 이미지를 못 얻은 그룹은 ⑪ 로.
  3. Sonnet 청크. 그룹을 깨지 않으면서 이미지 15장씩 청크 → 청크마다 1회 complete_json(SYSTEM, [텍스트, [그룹 gid] N장, 이미지…], schema). 스키마: groups[{group_id, parent(enum PARENTS), proposed_parent|null, concept, confidence}] 전부 required. 응답에 빠진 그룹은 ⑪ 로.
  4. 이름 통합. 청크가 2개 이상이면 텍스트만으로 1회 더(MERGE 프롬프트) — 같은 세트인데 표기만 다른 concept 을 통일. parent 가 같은 항목의 concept 만 교체. 실패해도 청크 결과 유지.
  5. 최근접 상속. VLM 에 안 간 그룹은 이름 붙은 그룹 중심과 코사인 → 거리 ≤ 0.25 면 그 parent/concept 상속(confidence = 1 − dist, assigned_by = nearest), 멀면 기타/기타 + needs_review.
  6. needs_review. VLM 그룹: confidence < 0.8 또는 (parent ≠ 기타 ∧ 사진들의 clip_parent 다수결 ≠ parent). 상속 그룹: parent ≠ 기타 ∧ clip_parent 다수결 ≠ parent. proposed_parent 는 parent 가 기타일 때만 저장.

시스템 프롬프트 원문 (naming.py SYSTEM)

당신은 웨딩 사진 스튜디오의 갤러리 정리를 돕는다. 비슷한 배경·구도로 찍힌 사진
묶음(그룹)마다 대표 사진이 1~2장 온다. 대표가 2장인데 서로 다른 세트로 보이면 그 그룹의
confidence를 낮춰라. 그룹마다 폴더 이름 두 층을 정한다.

- parent(큰 분류): 주어진 목록에서만 고른다. 어느 것에도 맞지 않으면 "기타"를 고르고
  proposed_parent에 더 맞는 큰 분류 이름을 제안한다 (맞는 것이 있으면 proposed_parent는 null).
- concept(컨셉): 촬영 세트를 부를 짧은 한국어 이름 (2~12자). 배경·소품·상황으로 짓는다
  (예: "소파", "케이크 테이블", "해변", "정원 산책"). 흑백/컬러 같은 스타일이나
  인물 구성(신부 단독 등)은 컨셉 이름에 넣지 않는다. 같은 세트로 보이는 그룹들에는 같은
  concept 이름을 붙인다.
- confidence: 이 배정에 대한 확신 0~1.

모든 그룹에 대해 답한다. 이미지에 보이지 않는 것을 지어내지 않는다.

# MERGE 프롬프트
웨딩 갤러리 폴더 이름 목록을 정리한다. 같은 촬영 세트·컨셉을 가리키는데 표기만
다른 concept 이름들(예: "소파 세트"와 "쇼파")을 하나의 표준 이름으로 통일한다. parent는 바꾸지
않는다. 다른 세트를 억지로 합치지 않는다. 모든 그룹을 다시 돌려준다.

Bedrock 호출 모양 (llm.py)

  • legacy AnthropicBedrock(aws_region="ap-northeast-2") — 서울에 Mantle 엔드포인트가 없어 InvokeModel 경로. 모델 global.anthropic.claude-sonnet-4-6(크로스 리전 프로필, 국외 전송). 서울 온디맨드에 Sonnet 이 없다.
  • output_config = {format: {type: "json_schema", schema}} 로 JSON 강제. number 에 min/max 를 못 써서 범위는 프롬프트에 맡기고 읽는 쪽에서 클램프. max_tokens 4096. stop_reason 이 refusal / max_tokens 면 RuntimeError.
  • 비용 상한: 이미지 호출 ≤ ⌈대표 이미지 수/15⌉ + 통합 1. 갤러리가 커져도 커버리지 85%·상한 120 그룹이 정한 범위를 넘지 않는다.
