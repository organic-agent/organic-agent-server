워커 루프

한다GPU 인스턴스 안 컨테이너가 photo_analysis 에서 32장을 FOR UPDATE SKIP LOCKED 로 집어 점수를 쓰고 commit(=잠금 해제)하며, 두 커넥션이 교대로 다음 배치를 미리 집는다. 큐가 비면 30초 뒤 자기 EC2 를 정지한다.왜워커가 갤러리를 배정받지 않고 스스로 집으면 wes 에 큐 관리가 필요 없고 워커 2대가 한 갤러리를 나눠 먹어도 중복이 0 이다. 잠금이 트랜잭션에 묶여 같은 커넥션으로는 다음 배치를 미리 못 잠그기 때문에 레인이 둘이다. 자기 정지는 wes 스윕(5초)보다 빠르고 wes 가 죽어도 동작한다.없으면wes 가 갤러리별 배정 컬럼을 관리해야 하고, GPU 가 배치 사이마다 놀며, 정지를 wes 에만 맡기면 wes 장애 시 GPU 가 켜진 채 남는다.입출력photo_analysis(embedding ∧ ¬clip_embedding ∧ error NULL) 32장 → clip_embedding · subjects · sub_scores · model_version · analyzed_at

실선은 호출·저장, 점선은 조회·상태 확인입니다. 박스를 누르면 해당 단계의 설명으로 이동합니다.

한 장의 계산 — Scorer.score

한다미리보기 한 장을 한 번 디코드해 CLIP 벡터, LAION 미학 점수, ARNIQA 기술 점수, zero-shot 피사체·부모 라벨, Laplacian 등 고전 지표를 한꺼번에 낸다. 묶음 실패는 한 장씩 후퇴.왜뒤 단계가 필요로 하는 것이 각각 다르다 — 백분위 순위(미학·기술), 폴더 칩(피사체), 그룹 이름 검증(부모 라벨), 그룹화의 C 축(CLIP 벡터), 이유 문장 재료(선명·클리핑). 한 번 디코드로 다 뽑아야 GPU 시간이 가장 싸고, 한 장 실패가 32장을 죽이지 않아야 한다.없으면단계마다 사진을 다시 열어 GPU 시간이 몇 배가 되고, 한 장의 디코드 실패로 배치 전체가 재시도된다.
  1. prepare. load_image(path) 1회 디코드 → classical.measure(긴 변 1024 그레이) → laion.prepare(224 CLIP 전처리) → arniqa.prepare(uint8 텐서). 디코드 스레드가 2묶음 앞서 준비.
  2. CLIP 벡터. open_clip ViT-L-14 / pretrained="openai", clip_batch(32)장 한 forward → .float() → L2 정규화 → 768d clip_embedding. 실패 시 한 장씩 재시도.
  3. ARNIQA 기술 점수. torch.hub miccunifi/ARNIQA@66d16eb, 회귀기 spaq, 입력 긴 변 1024 + half-scale 쌍, 같은 shape 끼리 arniqa_batch(8)장 forward → technical_score. 실패 시 한 장씩, 그래도 실패면 그 장만 failed.
  4. LAION 미학. CLIP 벡터 → MLP(768→1024→128→64→16→1, sac+logos+ava1-l14-linearMSE.pth, CPU) → aesthetic_score(클램프 없는 원 스칼라, 하류가 백분위로 바꿈).
  5. 피사체 zero-shot. 같은 CLIP 벡터와 4라벨 텍스트 벡터(라벨당 프롬프트 2개 평균) 코사인 argmax. 1·2위 차 margin < 0.01 이면 unknown. → subjects, sub_scores.subjects_margin.
  6. 부모 라벨 zero-shot. PARENTS 7종 중 프롬프트가 있는 6종(기타 제외) 코사인 argmax → sub_scores.clip_parent. categorize naming 이 VLM 부모와 대조해 needs_review 를 정한다.
  7. 고전 지표. sharpness = var(laplace(gray)), highlight_clip = #(gray ≥ 250)/n, shadow_clip = #(gray ≤ 5)/n, mean_luma = mean(gray)(0~255).
  8. flush. 32장마다 write_scores. Lambda 폴백은 남은 시간이 가장 오래 걸린 배치 + 60s 보다 적으면 stopped.

Lambda 폴백 — 같은 Scorer, 다른 입구

한다같은 Scorer 를 Lambda 입구로 감싼다. wes 가 보낸 photoIds 를 force=True 로 다시 계산해 UPSERT 한다.왜GPU 인스턴스가 없거나(운영 초기), 켜지지 않거나, 워커가 멈췄을 때도 점수가 나와야 잡이 끝난다. 계산 코드를 공유하니 결과가 워커와 같고, UPSERT 라 워커와 겹쳐도 같은 값을 덮을 뿐이다.없으면GPU 장애 = 파이프라인 정지. 폴백이 다른 코드면 GPU 와 Lambda 의 점수가 달라 백분위가 섞인다.
