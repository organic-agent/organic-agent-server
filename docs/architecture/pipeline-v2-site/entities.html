엔티티 필드 사전 — 어떤 값이, 누구 손에서, 언제 채워지나

파이프라인은 HTTP 로 데이터를 나르지 않고 테이블을 인터페이스로 쓴다. 그래서 컬럼 하나하나에 "누가 쓰는가"가 계약이다. 여기서는 사진·분석·잡·배정·폴더 일곱 테이블의 모든 컬럼을 뜻 · 쓰는 주체 · 채워지거나 바뀌는 시점으로 풀어 적는다. BaseEntity 가 주는 version · created_at · updated_at 도 표에 넣었다.

ai_concept_jobs 는 없다
요청에 적힌 ai_concept_jobs 라는 테이블·엔티티는 현재 코드·스키마에 존재하지 않는다. 그 역할은 둘로 나뉘어 있다 — 갤러리 한 번의 "그룹·이름·폴더" 잡은 ai_analysis_jobs, 그 잡이 남긴 그룹별 이름 배정은 ai_concept_assignments. 아래에 둘 다 있다.

한 장의 시간순 — 어느 단계에서 어떤 컬럼이 채워지나

① 발급
브라우저→wes photos 행 INSERT: gallery_id · storage_key · original_file_name · content_type · display_order · status=PENDING · upload_url_expires_at. photo_analysis 행은 아직 없다.
② PUT · complete
브라우저 S3 PUT 뒤 complete → wes photos.status=UPLOADED. 통보가 없으면 PendingUploadSweeper 가 1분 뒤 HeadObject 로 같은 값을, 24h 없으면 deleted_at.
③ 배정
wes 5초 스윕이 50장 집으며 photos.dispatched_at · embed_attempts. 10분 뒤 벡터가 없으면 dispatched_at=NULL, 3회 넘으면 photo_analysis.error=EMBED_ATTEMPTS_EXCEEDED(행이 여기서 처음 생길 수도 있다).
④ 임베딩
embedder photo_analysis 행 UPSERT: embedding · embedding_model. 같은 트랜잭션에 photos.preview_key + EXIF 9컬럼(taken_at … byte_size).
⑤ 점수
score photo_analysis UPSERT: clip_embedding · subjects · sub_scores · model_version · analyzed_at. 실패는 error=PREVIEW_MISSING|SCORE_FAILED.
⑥ 잡 생성
브라우저 POST /ai-analysis → wes ai_analysis_jobs INSERT(status=ANALYZING). 잡은 사진 컬럼을 쓰지 않고 관측만 한다.
⑦ categorize
wes status=CATEGORIZING · dispatched_at · attempts → categorize photo_analysis.technical_pct · aesthetic_pct · cluster_id · cluster_rank · embed_group_id · sub_scores(+sharpness_pct·rank_reason) · analyzed_at, 그리고 ai_concept_assignments INSERT. 실패면 ai_analysis_jobs.error 만.
⑧ 물질화
wes concept_folders · detail_folders · photo_category_assignments INSERT → ai_analysis_jobs.status=DONE · finished_at.
⑨ 편집
사용자 폴더 이름·순서·사진 이동·삭제. photo_category_assignments.assigned_source=USER 가 되면 재물질화가 그 사진을 건드리지 않는다.

photo_category_assignments — PhotoCategoryAssignment

category/domain/PhotoCategoryAssignment.kt · PK photo_id(사진은 갤러리 전체에서 한 폴더에만) · 인덱스 (detail_folder_id, photo_id)

사진 한 장이 어느 세부폴더에 들어 있는지를 잇는 행. photo_id 가 PK 라 사진은 갤러리 전체에서 한 폴더에만 속한다. AI 물질화가 JDBC batch 로 만들고, 사용자가 사진을 옮기면 같은 행이 USER 로 덮인다. 이 행의 존재 여부가 재물질화의 "이미 배정된 사진 제외" 기준이다 — 소스가 AI 든 USER 든 행이 있으면 다시 배정하지 않으므로 사용자가 옮긴 사진이 보호되고, 미분류로 뺀 사진(행 삭제)은 다음 물질화 대상이 된다.

읽을 때 기억할 규칙

  • 컬럼 소유권이 곧 계약. embedder 는 photo_analysis 벡터 두 컬럼 + photos preview_key·EXIF 만, score 는 다섯 컬럼, categorize 는 백분위·그룹 컬럼 + ai_concept_assignments + ai_analysis_jobs.error 만 쓴다. 서로의 컬럼은 SET 절에 없다. 정본은 .claude/rules/migration.md.
  • "없음 = 아직". photo_analysis 행이 없거나 컬럼이 NULL 이면 그 단계가 아직이라는 뜻이고, 카운트 쿼리는 LEFT JOIN 으로 이를 센다. 상태 enum 은 PhotoStatus 2개와 AnalysisStatus 4개뿐이다.
  • 실패는 error 하나. 사진 단위 photo_analysis.error, 잡 단위 ai_analysis_jobs.error. 읽는 쪽 전부가 error IS NULL 을 조건에 넣는다.
  • 재분석 = 리셋. photo_analysis DELETE + photos.dispatched_at=NULL, embed_attempts=0. 폴더·추천은 photo_id 로 사진을 가리키므로 남는다. 새 잡이 새 폴더 세트를 만들지만 이미 배정된 사진은 건드리지 않는다.
  • photoselect 롤 권한. AI 가 쓰는 DB 유저는 photos SELECT(+embedder 롤의 특정 컬럼 UPDATE), photo_analysis 전부, ai_concept_assignments INSERT/UPDATE, ai_analysis_jobs 는 UPDATE (error, updated_at) 뿐. photo_ratings·photo_selections·수동 배정은 AI 접근 금지.
