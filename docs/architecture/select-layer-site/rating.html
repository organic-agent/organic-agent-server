사진 별점 — 사진마다 한 칸, 부부가 공유하고 작가에게는 숨긴다

별점은 photo_ratings 에 사진당 1행이다. 신랑·신부가 같은 칸을 덮어쓰고 마지막 값이 남는다. 사용자별 별점도, 평균도 없다. 작가(스튜디오 멤버)는 매길 수도 볼 수도 없고, 하객(협업)도 볼 수 없다. 같은 photo 패키지의 부부 댓글(photo_comments)도 함께 적는다.

별점 주기 · 지우기 — rate() / clear()

한다사진 한 장에 1~5 점을 매기거나 지운다. 행이 있으면 덮어쓰고 없으면 만든다. 새로 매기든 덮어쓰든 200, 매긴 적 없어도 DELETE 는 204.왜별점은 부부가 "이 사진 어때?"를 서로에게 남기는 공유 메모다. 사용자별 칸을 두면 두 값을 화면에 어떻게 합칠지(평균? 최대?)를 정해야 하고, 그 답이 없다. 한 칸을 공유하고 마지막 사람이 이기는 것이 부부의 실제 대화와 같다. 작가를 거부하는 것은 작가가 고객 대신 사진을 고르지 못하게 하는 원칙(requireSelectionEditor)이다.없으면신랑과 신부의 별이 따로 쌓여 화면이 둘 중 무엇을 보여줄지 흔들리고, 작가가 별점으로 고객의 취향을 미리 읽는다.입출력PUT …/photos/{p}/rating {score} → {photoId, score, ratedBy, updatedAt} · DELETE → 204

누가 별점을 보나 — PhotoResponse.score

한다사진 응답의 score 필드에 별점을 싣되, 스튜디오 관리자와 하객에게는 항상 null 로 지운다. 목록은 findAllByPhotoIdIn 한 번으로 채운다.왜별점은 부부의 사적 판단이라 작가·하객에게 새어 나가면 안 된다는 원칙이 응답 조립 한 곳에 있어야 화면마다 빠뜨리지 않는다. 목록 필터 minScore 를 스튜디오 뷰어에게 403 으로 막는 것도 같은 이유 — 필터 결과로 별점을 역추론할 수 있기 때문이다.없으면작가가 사진 목록에서 고객의 별을 보고 셀렉을 유도하거나, 하객 화면에 부부의 취향이 드러난다.
