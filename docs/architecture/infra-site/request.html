아키텍처

Route 53 · ACM · ALB

  1. Route 53. api.easyselect.kr A 별칭 → ALB(evaluate_target_health=false). 존은 dns/ 스택 소유, 앱 스택은 이름으로 조회만.
  2. ACM. api.easyselect.kr 인증서, DNS 검증(검증 CNAME은 TTL 60·allow_overwrite). HTTPS 리스너가 aws_acm_certificate_validation을 참조해 검증 완료를 기다립니다.
  3. ALB wes. internet-facing, public 서브넷 두 곳(두 AZ 필수), SG wes-alb. 리스너 :80은 :443으로 HTTP_301, :443은 ELBSecurityPolicy-TLS13-1-2-2021-06.
  4. 리스너 규칙 priority 1. /internal/admin, /internal/admin/* → 고정 응답 404 {"message":"Not Found"}. 관리자 API는 공개 경로로 절대 나가지 않습니다. HTTP는 전량 리다이렉트라 우회 경로가 없습니다.
  5. 타깃 그룹 wes-app. HTTP :8080, target_type=instance, 헬스체크 /actuator/health matcher 200-399(느슨함, 나머지는 AWS 기본값). 타깃은 EC2 한 대를 고정 등록한 것이고 ASG는 없습니다.

부팅과 설정

user_data는 스무 줄이고 앱을 설치하지 않습니다. Docker·compose v2 설치, ubuntu를 docker 그룹에, 2 GB 스왑, snap aws-cli가 전부입니다. 앱 컨테이너는 서버 repo의 CD가 SSM Run Command로 /opt/wes-prod에서 docker compose pull && up을 실행해 올립니다(GHCR arm64 이미지). 앱은 Spring Cloud AWS로 /wes/prod/를 통째로 읽으므로 환경변수 주입이 없습니다.

배포가 닿는 방법

SSH 없이, 장기 액세스 키 없이. 서버 repo main에 머지되면 GitHub Actions가 OIDC로 wes-deploy-* 롤을 맡고 ssm:SendCommand(AWS-RunShellScript, 대상은 태그 Name=wes-app인 인스턴스만)로 compose를 갱신합니다. 자세한 롤 구성은 7. 운영 · 배포.
