VPC 하나, 서브넷 넷, NAT 없음

서울 리전 한 계정에 VPC 10.0.0.0/16 하나를 두고 AZ 2a·2c에 public 서브넷과 DB 서브넷을 한 쌍씩 만듭니다. DB 서브넷에는 인터넷 라우트가 없고 S3 게이트웨이 엔드포인트와 bedrock-runtime 인터페이스 엔드포인트만 붙습니다. 보안 그룹은 여섯 개이며 규칙은 전부 SG 참조로 묶여 있어 사설 경로 안에서만 통합니다.

왜 NAT가 없나
DB 서브넷의 워크로드(Lambda·RDS)가 필요로 하는 바깥은 S3와 Bedrock뿐이라 엔드포인트 둘로 끝납니다. NAT 게이트웨이의 시간당 과금을 피하고, Lambda가 인터넷으로 나갈 수 없다는 사실 자체가 경계가 됩니다. AZ는 2a·2c만 씁니다(2b·2d는 쓰는 인스턴스 타입을 지원하지 않음).

인터페이스 엔드포인트의 SG wes-vpce-*는 :443 ← 10.0.0.0/16(VPC CIDR)입니다. SG 참조 대신 CIDR을 쓴 이유는 security → network 모듈 순환을 피하기 위해서입니다. db_subnet_ids 출력이 두 엔드포인트에 depends_on을 걸어, 이를 쓰는 analysis·database 모듈이 엔드포인트 준비를 기다립니다.

보안 그룹 여섯

모든 SG는 name_prefix + create_before_destroy이고 규칙은 인라인이 아니라 별도 aws_vpc_security_group_*_rule 리소스입니다. SSH 규칙은 ssh_allowed_cidr가 null(기본)이면 아예 만들지 않습니다.

DNS 스택 분리

Route 53 호스티드 존 easyselect.kr은 별도 dns/ 스택(state 키 dns/terraform.tfstate)이 소유하며 리소스는 존 하나뿐입니다. 앱 스택을 destroy해도 존과 NS 위임이 남게 하려는 것입니다(존을 재생성하면 NS가 바뀌어 등록기관 재위임이 필요). 앱 스택은 존을 이름으로 조회만 하고, 레코드는 각 모듈이 만듭니다.
