모니터링, 테스트 프론트, 그리고 SSH 없는 배포

앱과 관리자 API는 로그를 wes-monitoring의 Loki로 밀어 넣고 Grafana로 봅니다. 프론트 테스트 서버는 test.easyselect.kr에 따로 있습니다. 모든 배포는 GitHub Actions가 OIDC로 임시 자격증명을 받아 ECR push·Lambda 코드 갱신·SSM Run Command로 수행하며, 장기 액세스 키와 SSH는 없습니다. 인프라 자체는 PR에서 plan, main 머지에서 apply입니다.

로그를 보내는 쪽은 wes-app과 wes-admin-api의 logback appender입니다. SSM app.logging.loki-url이 http://<사설 IP>:3100/loki/api/v1/push인 이유는 :3100 ← wes-ec2 · wes-admin SG 규칙이 VPC 사설 경로에서만 매칭되기 때문입니다. Grafana 비밀번호는 /wes/monitoring/grafana.admin-password 수동 SecureString이며 없으면 user_data가 멈춥니다.

테스트 프론트 wes-frontend-test

  • 인스턴스. Ubuntu 24.04 arm64 · t4g.small · EIP · test.easyselect.kr. SG는 :80/:443 인바운드, 이그레스도 80/443만. 롤은 아티팩트 버킷 releases/* GET 허용 + ssm:GetParameter* /wes/* 명시적 Deny.
  • Caddy. 다이제스트 고정 caddy:2.10.2-alpine, host 네트워크, HSTS·noindex, /infrastructure-health 200, reverse_proxy 127.0.0.1:3000(Next standalone).
  • 배포. test-web CD가 releases/<sha>.tar.gz를 S3에 올리고 고정 SSM 문서 wes-frontend-test-deploy만 부릅니다(AWS-RunShellScript 불가, 인스턴스 ID 고정). 문서는 세 인자를 정규식으로 검증하고 deploy-command.sh를 실행 — 이미지 빌드, 비루트 UID 1001·읽기 전용 rootfs·CapDrop ALL·메모리 768 MiB·pids 256 검증, /health·/version.json 확인, 실패 시 롤백.
  • 알람. wes-frontend-test-status-check(StatusCheckFailed > 0, 2분). 액션 없음.

State. 사전 생성(bootstrap, 코드 밖) S3 wes-tf-state-<account>, 암호화·버저닝, S3 네이티브 락(use_lockfile=true, DynamoDB 없음). 키는 app/terraform.tfstate와 dns/terraform.tfstate. 요구 버전 Terraform ≥ 1.11(ephemeral·write-only), aws provider ~> 5.60. modules/github-actions 변경은 닭과 달걀 문제라 로컬 apply.

배포 순서 (재구축 시)

  1. dns 스택 apply (한 번). 존·NS 위임.
  2. 수동 SSM 등록 — DB 비밀번호 셋 · JWT · OAuth · cors.allowed-origins(apply 입력) · Grafana 비밀번호 · Tailscale auth key.
  3. ECR만 먼저 apply(-target=module.analysis.aws_ecr_repository.this) → Lambda 이미지 셋 push(linux/amd64, embedder는 HF 토큰 필요). wes-score:gpu는 AI repo CD가 만듦.
  4. 앱 스택 전체 apply. 이후 Image Builder를 한 번 돌려 AMI를 gpu_ami_id에 핀하고 재apply.
  5. 롤 ARN을 각 저장소 시크릿·변수에 등록.
  6. 서버 main 머지 → CD → Flyway가 스키마 생성.
  7. DB 사용자 생성·상한 설정 · Lambda DB_PASSWORD 주입(read-merge-write).
  8. 확인. 1~2는 한 번, 3~5는 재구축마다, 6·8은 매 배포, 7은 새 DB일 때만.

destroy를 견디는 것: Route 53 존, /wes/prod/*·/wes/monitoring/* 수동 파라미터, GHCR 이미지, 롤 ARN 시크릿(단, 롤 이름 접미사가 바뀌므로 갱신 필요).
