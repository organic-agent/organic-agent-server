엔티티 필드 사전 — 추천이 쓰는 행과 읽는 행

추천 도메인이 쓰는 테이블은 ai_selection_jobs 와 ai_recommendations 둘이다. 셀렉(photo_selections · photo_selection_items)과 폴더 세트는 읽기만 한다. 각 컬럼을 뜻 · 쓰는 주체 · 채워지거나 바뀌는 시점으로 적는다. 분석 결과 테이블(photo_analysis 등)은 분석 파이프라인 사전 에 있다.

잡 한 번의 시간순 — 어느 단계에서 어떤 컬럼이 채워지나

① 요청
브라우저→wes photo_selections 가 없으면 INSERT. ai_selection_jobs INSERT: selection_id · mode · folder_set_job_id · detail_folder_id · request_prompt · requested_target_count · status=PENDING.
② claim
runner status=RUNNING · started_at (조건부 UPDATE).
③ 질의
runner prompt 가 있으면 resolved_query(한 번만).
④ 1단계
runner 범위 사진의 ai_recommendations DELETE(거절 제외) → INSERT round · rank · folder_id · score_breakdown · presented_at, reason=NULL. 같은 트랜잭션에 ai_selection_jobs.round.
⑤ 2단계
runner 10장 배치마다 ai_recommendations.reason UPDATE.
⑥ 종료
runner status=DONE · finished_at · result 또는 FAILED · finished_at · error.
⑦ 편집
사용자 담기·빼기는 photo_selection_items INSERT/DELETE(셀렉 API). 다음 refine 라운드의 제외·선호 재료가 된다. rejected_at 을 쓰는 API 는 아직 없다.
⑧ 복구
wes 기동 시 RUNNING 잡 status=PENDING · started_at=NULL. round 가 있으면 다시 집었을 때 ⑤ 만 돈다.

ai_recommendations — AiRecommendation

라운드 단위로 쌓이는 추천 한 건. refine 은 이전 라운드를 고치지 않고 새 라운드를 통째로 적으며, 범위 사진의 옛 행은 1단계에서 지운다(거절 행 제외). 조회는 사진별 최신 라운드 한 행만 본다.

읽을 때 기억할 규칙

  • 쓰기는 두 테이블. 요청 서비스는 ai_selection_jobs 만, 실행기는 잡의 상태 컬럼과 ai_recommendations 만 쓴다. 셀렉·폴더·분석 결과는 읽기 전용이다.
  • 라운드는 append. 새 라운드가 이전 라운드를 덮지 않는다. 화면이 보는 것은 사진별 최신 라운드 한 행이고, 1단계 DELETE 는 범위 사진의 옛 행만 정리한다(거절 행 제외).
  • 반응 컬럼은 예약 상태. rejected_at 은 읽기만, accepted_at · unselected_at · accept_mode 는 매핑조차 없다. 담기 반응은 photo_selection_items 를 읽어 대신한다.
  • round 가 복구의 열쇠. 잡의 round 가 있으면 추천은 이미 저장된 것이고 이유만 다시 채운다. 없으면 처음부터.
