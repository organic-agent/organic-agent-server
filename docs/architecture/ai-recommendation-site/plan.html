FolderFitRule — 상수의 뜻

한다폴더 안에서 임베딩이 동떨어진 사진을 찾아 추천 후보에서만 뺀다(배정은 그대로).왜AI 폴더 배정은 그룹 단위라 한두 장이 잘못 섞일 수 있다. 그런 사진이 점수가 높으면 "해변" 폴더 대표로 실내 컷이 뽑힌다. 중앙값·MAD 기반의 강건 통계를 써서 폴더가 균일하든 아니든 같은 기준으로 잡고, 20% 넘게 잡히면 폴더 자체가 잡동사니라 보고 손대지 않는다.없으면폴더 이름과 맞지 않는 사진이 그 폴더의 1위로 추천돼 이유 문장까지 "해변 폴더 41장 중 1위"라고 말한다.입출력emb[], folder members → 제외할 photoId 집합 (결과는 result.misfitPhotoIds)

RecommendationScoring — 산식 원문

한다사진마다 하나의 점수를 만든다. 기본은 기술·미학 백분위의 평균을 z 정규화한 값이고, 담은 사진이 충분하면 "부족한 유형"과 "선호하는 유형"에 가산점을 붙인다.왜두 모델 점수는 단위가 달라 그대로 더할 수 없다 — 갤러리 안 백분위로 맞추면 폴더 범위 요청에서도 같은 자로 잰다. 균형·선호 항은 refine 을 위한 것이다: 부부가 신부 단독을 많이 담았으면 두 분 컷을, 단체를 안 담았으면 단체를 채워 준다. 담은 사진이 5장 미만이면 통계가 노이즈라 끈다.없으면점수가 높은 유형만 반복 추천되고, 담기·빼기가 다음 라운드에 아무 영향을 주지 않는다.입출력technical_pct[], aesthetic_pct[], subjects[], selected[] → score[], prior_z, balance_z, affinity_z
prior(p) = w_t·technical_pct + w_a·aesthetic_pct          (갤러리 내 백분위, w_t = w_a = 0.5)
score(p) = z(prior) [+ w_bal·z(deficit(type p)) + w_pref·z(affinity(type p))]   (w_bal = w_pref = 0.5)

type      = photo_analysis.subjects (bride/groom/couple/group/unknown)
deficit   = max(0, poolShare(type) − selectedShare(type))      담은 사진에서 부족한 유형
affinity  = P(sel | type) − P(sel)                              담은 사진이 선호하는 유형 (lift)
대괄호 게이트: SUBJECTS_TRUSTED ∧ 담은 사진 ≥ PREF_MIN_SELECTED(5) ∧ unknown 아닌 유형 존재. 아니면 z(prior) 만.
z(): 표준편차가 0 이면 0 벡터.
품질로 지우지 않는다
sharpness · highlight_clip · shadow_clip 은 점수에 들어가지 않는다. 이유 문장의 재료(선명함·노출 안정)와 형제 탈락 이유에만 쓰인다. 코드 주석: "품질로 사진을 제거하는 단계는 없다 — 점수 하한은 근거 문장에서 품질 표현을 빼는 게이트일 뿐이다."

쿼터

한다폴더마다 몇 장을 추천할지(n_f) 배분한다. 요청 장수가 없으면 목표(maxSelectablePhotoCount−담은 수)를 폴더 크기에 비례해 나누고, 있으면 그 장수를 후보 수에 비례해 나눈다.왜추천 총량은 앨범 목표에 맞아야 하고, 폴더 크기가 10배 차이 나도 작은 폴더가 0장이 되면 안 된다(폴더 화면에 AI 마크가 하나도 없는 게 더 이상하다). 반대로 한 폴더의 절반 넘게 추천하면 추천이 아니다. 그래서 하한 1·상한 ⌈|f|/2⌉ 을 둔다. 폴더 하나만 다시 받아도 세트 전체로 배분해 장수가 널뛰지 않게 한다.없으면큰 폴더가 목표를 다 먹거나, 작은 폴더가 비거나, 요청한 12장이 반올림 때문에 14장이 된다.입출력sizes{folder → |f|}, target 또는 capacities{folder → 클러스터 수}, requested → quota{folder → n_f}
// requestedCount 없음 — FolderQuota (AI repo rerank.folder_quota 의 자리)
n_f = max(1, round(target · |f| / Σ|f'|)),  단 n_f ≤ max(1, ceil(|f| · CAP_RATIO 0.5))
target ≤ 0(담은 사진이 목표에 닿은 뒤 refine)이어도 폴더마다 1장 — 폴더 화면에서 AI 마크가 사라지는 것이 더 이상하다

// requestedCount 있음 — ExactRecommendationQuota

n_f = floor(min(requested, Σcap) · capacity_f / Σcap), 나머지는 잔여 큰 순으로 +1 (용량 초과 없음)

MmrSelector

한다폴더 안 후보에서 연사 클러스터당 최고점 한 장만 남기고, 점수와 "이미 고른 것과의 유사도"를 저울질(MMR)해 n_f 장을 고른다. 순위는 점수순.왜웨딩 사진은 같은 순간 연사가 5~8장씩이라 점수만 보면 같은 컷이 줄지어 뽑힌다. 연사는 대표 한 장으로 접고, 남은 후보끼리도 임베딩이 겹치면 감점해 배경·구도가 다른 컷이 섞이게 한다. λ=0.7 은 "점수 7 : 다양성 3".없으면추천 10장이 같은 포즈 10장이 된다. 순위를 MMR 순서로 매기면 다양성 때문에 뽑힌 컷이 1위가 되므로 순위는 점수순으로 따로 둔다.입출력score[], emb[], members, clusterIds, quota → picks[{index, folderRank, quota}]
candidates = 폴더 사진 − exclude − misfit → 연사 클러스터당 score 최고 1장
repeat quota:
    pick = argmax_c  LAMBDA 0.7 · score[c] − 0.3 · maxSim[c]        (maxSim = 이미 고른 것들과의 최대 코사인)
    maxSim 갱신
folderRank = 후보(연사 dedup 후)의 점수 내림차순 순위 (MMR 순서가 아니다)

persistRound — 1단계 저장

한다메모리의 draft 를 새 라운드 번호로 ai_recommendations 에 적고, 같은 트랜잭션에서 잡에 round 를 박는다. 범위 사진의 옛 추천은 지우되 거절 행은 남긴다.왜여기가 "화면에 순위가 뜨는 순간"이다. 이유 문장(LLM, 수십 초~분)을 기다리지 않고 순위부터 보여 주려면 저장을 두 단계로 나눠야 한다. 라운드를 덧쓰지 않고 새로 적는 이유는 refine 이 "담기·빼기 이후의 판단"이라 이전 판단과 구분돼야 하고, 거절 행은 다음 라운드의 제외 근거라 지우면 안 되기 때문이다.없으면사용자가 이유가 채워질 때까지 빈 화면을 보거나, 폴더 하나만 다시 받았는데 다른 폴더의 추천이 사라지거나, 거절한 사진이 다시 추천된다.입출력world, draft → 라운드 번호 (행: round, rank, folder_id, score_breakdown, presented_at, reason=NULL)
