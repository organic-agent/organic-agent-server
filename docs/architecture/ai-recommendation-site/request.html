요청·조회 — 엔드포인트는 둘, 반응 API 는 아직 없다

POST 가 잡을 만들고 GET 이 최신 잡과 사진별 최신 추천을 돌려준다. "최신 잡 GET"은 따로 없고 목록 응답의 job 으로 온다. 담기는 셀렉 API(/photo-selection/photos)이고 추천 도메인은 그것을 읽기만 한다. 거절(rejected_at)을 쓰는 API 는 아직 없다.

request() — 게이트 순서

한다"이 셀렉에 AI 추천 한 판 돌려 달라"는 요청을 검증하고 잡 행 하나로 바꾼다. 계산은 하지 않는다 — 계산은 몇 초에서 몇 분이 걸리므로 HTTP 스레드에서 돌리지 않고, 행을 만들어 두고 202 로 즉시 답한다.왜추천은 사진 수백 장의 백분위·임베딩·폴더를 읽고 LLM 을 두 번 부르는 무거운 일이다. 요청 시점에 할 수 있는 것(권한·입력 형식·폴더 세트 존재·중복 실행)만 여기서 가려내 잘못된 요청을 빨리 거절하고, 나머지는 잡으로 넘겨 화면이 폴링으로 지켜보게 한다.없으면같은 셀렉에 잡이 둘 이상 돌아 라운드가 꼬이거나, 폴더 세트가 없는 갤러리에서 빈 추천이 만들어지거나, 제출된 앨범이 바뀐다. 게이트가 순서대로 있는 이유는 싼 검사(권한·형식)를 먼저, 비싼 검사(DB 조회)를 나중에 하기 위해서다.입출력{analysisJobId?, detailFolderId?, prompt?, targetCount?} → ai_selection_jobs 행(PENDING) + 202 AiSelectionJobResponse
  1. 인가. requireSelectionEditor(galleryId, userId) → 403 GALLERY_403_1 등.
  2. 문장·장수 형식. prompt.isBlank() || length > 1000, targetCount !in 1..500 → 400 RECOMMENDATION_400_2 INVALID_QUERY.
  3. 폴더 존재. detailFolderId 가 있으면 aiFolderSetReader.detailFolder 로 확인 → 404 RECOMMENDATION_404_4. 세트 밖(사용자 생성) 폴더도 허용.
  4. 기준 세트. resolveFolderSetJobId: analysisJobId 지정 시 setExists 아니면 404 RECOMMENDATION_404_2; 생략 시 latestSetJobId. 세트가 없는데 갤러리 전체 라운드(폴더 미지정)면 409 RECOMMENDATION_409_5. 폴더 범위 요청은 세트 없이도 통과(null 허용).
  5. 셀렉. photo_selections 를 갤러리로 찾고 없으면 만든다. requireEditable() — 제출된 앨범이면 SELECTION_409_1.
  6. 활성 잡. existsBySelectionIdAndStatusIn(ACTIVE={PENDING,RUNNING}) → 409 RECOMMENDATION_409_6. 부분 유니크 uk_ai_selection_jobs_active 충돌도 같은 코드.
  7. 모드. 이 셀렉에 추천 행이 하나라도 있으면 refine, 없으면 draft. 프론트는 모드를 고르지 않는다.
  8. INSERT · 활동 · 실행. saveAndFlush(AiSelectionJob) → activityRecorder.recordGallery(MANDATORY 전파) → 로그 AI 추천 요청: galleryId=… mode=… jobId=… → afterCommit { launcher.launch(jobId) }. 커밋 전에 넘기면 실행기가 안 보이는 행을 집으려다 실패한다.

list() — 목록 조립

한다셀렉의 최신 잡과 사진마다 가장 최근 라운드의 추천 한 건을 현재 폴더 기준으로 걸러 돌려준다. 폴링의 유일한 응답이라 "잡이 어디까지 왔나"와 "무엇이 추천됐나"를 한 번에 준다.왜추천은 라운드 단위로 쌓이고(refine 이 새 라운드를 덧붙인다) 사진은 사용자가 폴더를 옮길 수 있다. 화면은 "이 폴더에 지금 들어 있는 사진 중 최신 추천"만 필요하므로, 라운드 병합·거절 제외·현재 배정 필터·담김 여부를 서버가 한 번에 계산해 주는 게 맞다.없으면프론트가 여러 라운드를 스스로 합쳐야 하고, 추천 당시 폴더(folder_id)와 지금 폴더가 달라 다른 폴더에 추천 칩이 새어 나간다. 잡 상태를 따로 조회하는 왕복도 하나 더 생긴다.입출력?folderId= → {round, job, photos[{folderId(현재), rank, reason, reasonReady, selected, photo}], viewUrlTtlSeconds}
selection = photo_selections WHERE gallery_id          // 없으면 empty(viewUrlTtl)
job       = ai_selection_jobs ORDER BY id DESC LIMIT 1  // 응답 job (스튜디오 뷰어면 prompt=null)
round     = ai_recommendations ORDER BY round DESC LIMIT 1 ?: photos=[] 로 반환
rows      = ai_recommendations WHERE selection_id (전 라운드)
            .groupBy(photoId).map { maxBy(round) }        // 사진마다 가장 최근 라운드 1행
            .filter { rejectedAt == null }
current   = FolderSetReader.detailIdsByPhotoId(rows.photoIds)   // 현재 배정 (추천 당시 folder_id 아님)
if folderId: rows = rows.filter { current[photoId] == folderId }
sort by (current folder id nullsLast, rank)
photos    = Photo 갤러리 스코프 조회 + PhotoViewAssembler(viewUrl) + photo_selection_items ∋ photoId → selected
응답 항목 AiRecommendationResponse뜻
folderId현재 배정 세부폴더(미분류 null). DB 의 folder_id(추천 당시)와 다를 수 있다
rank폴더 안 순위, 1 이 대표
reason · reasonReady이유 문장 · reason != null 의 계산값(컬럼 아님). 2단계 배치가 끝날 때마다 뒤집힌다
selectedphoto_selection_items 에 있음. 프론트는 자체 selectedSet 을 쓰고 이 값은 읽지 않는다
photo · roundPhotoResponse(viewUrl 포함) · 그 행의 라운드
노출 안 함score_breakdown · 점수 · 폴더 이름 · primary_reason — DB 와 잡 result 에만

jobId · selectionId · mode(DRAFT|REFINE) · status · folderSetJobId · detailFolderId · round(끝나기 전 null) · startedAt · finishedAt · error · createdAt · prompt · targetCount · resolvedDetailFolderIds · resolvedTargetCount · queryResolved · recommendedCount(=result.k) · shortfallCount

resolveFolderSetJobId — 어떤 폴더 세트를 기준으로 삼나

한다요청이 가리키는 AI 폴더 세트(= 분석 잡 id)를 정한다. 지정하면 존재를 확인하고, 생략하면 최신 세트를 고른다.왜추천은 "폴더마다 몇 장"을 세트 기준으로 배분한다. 어느 세트였는지를 잡에 박아 두면(folder_set_job_id) 나중에 재분류로 세트가 바뀌어도 "이 추천은 어느 폴더 구성에서 나온 것"인지 재현할 수 있다.없으면세트가 없는 갤러리에서 갤러리 전체 라운드를 돌리면 폴더 쿼터를 계산할 수 없어 예외로 죽는다. 그래서 폴더 미지정 요청은 세트를 필수(409_5)로 하고, 폴더 하나만 다시 받는 요청은 세트 없이도 허용한다.

  • folderSetJobId 불일치("추천을 다시 받으세요") 처리는 없다. 타입에만 있고 화면이 비교하지 않는다 — 폴더 세트가 바뀌어 낡은 추천이 남는 상황을 프론트가 감지하지 못한다.
