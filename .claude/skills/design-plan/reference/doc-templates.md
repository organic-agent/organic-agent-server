# 계획 문서 모양

`docs/`는 gitignore된 개인 폴더다. 계획은 `docs/plans/<작성일 YYYY-MM-DD>/`에 둔다.

## 상태 머리말 (모든 계획 문서 맨 위)

```markdown
# <결과를 말하는 한국어 제목>

> <왜 → 무엇 한 문장>
> 유형: B3 복잡한 기능 추가 · 태그: +스키마 +계약
> 이슈: #123 · 브랜치: feat/123-retouch-round
> 상태: 단계 2/6 (드라이버) 진행 중 · 갱신 2026-10-08
> 단계: 1 요구 ✔ · 2 드라이버 ▶ · 3 대안 · 4 트레이드오프·결정 · 5 API 계약 · 6 구현 계획
```

상태 값: `단계 n/N (<이름>) 진행 중` → `계획 확정 · 구현 중` → `PR #N` → `완료`.
Phase R(이어 하기)은 `이슈: #<번호>`와 `상태:` 줄을 읽는다 — 형식을 바꾸지 않는다.

## 폴더 (B5 · B7)

`docs/plans/<날짜>/<이름>/`

| 파일 | 내용 |
|---|---|
| `README.md` | 상태 머리말 + 단계 표(칸 · 문서 · 상태) + ADR 목록 + 계획 변경 기록 |
| `01-drivers.md` | 요구 분류 · 품질 속성 시나리오(6칸, 측정은 숫자) · 제약 · 가설 · 협의 결과 |
| `02-baseline.md` | 측정 정의 · 재현 방법(스크립트) · 회차 표 · 결과 · 가설 판정 (B5는 특성화 테스트 목록과 결과) |
| `03-options.md` | 제외 조건 · 시나리오별 택틱 → 패턴 · 트레이드오프 매트릭스("아무것도 안 함" 포함) |
| `adr/NNNN-<제목>.md` | 왜 · 선택지 · 고른 것 · 얻는 것/감수할 것 · 조정 손잡이 · 재검토 조건 · 상태(제안/채택/대체됨) |

`docs/design-method/templates/`(작성자 로컬, gitignore)가 있으면 그 템플릿을 복사해 쓰고, 없으면 위 표의 칸대로 쓴다. 칸 이름의 뜻은 [glossary.md](glossary.md).

## 오늘 일기 (B5 · B7이 여러 날일 때)

`docs/plans/<오늘>/<이름>-day.md` — 폴더는 계속 고쳐 쓰는 지식, 오늘 일기는 그날만.

```markdown
# <날짜> — <오늘 할 일 한 줄>
> 지식: [../<시작일>/<이름>/](…)
## 0. 오늘의 목표
| # | 목표 | 끝난 상태 | 산출물 |
## 1. 순서 (타임박스)
## 2. 오늘 하지 않는 것
## 3. 막히면
## 4. 오늘 기록
| 시각 | 무엇 | 결과 | 다음 |
```

결과 숫자는 오늘 일기에서 지식 폴더(02·03)로 옮긴다.

## 설명 자료 (Phase 8)

- HTML: 그림 위주, W²HO 순서(왜 → 무엇 → 어떻게 → 판단), 결정과 트레이드오프가 한 화면에.
- md: `<이름>-explained.md`, 한 화면(약 40줄) 안. 청중이 결정자면 "어떻게"는 요약하고 링크.
